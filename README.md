# SourceLab · 科研助手最小可运行闭环

SourceLab 是面向科研阅读与文献整理的科研助手 agent。系统把文献 PDF/OCR 逐页解析、版本感知检索、可跳转的原文证据、参考文献下钻、局域引文图、多篇 Future Work 线索、翻译对照与科研写作草稿串成一条可审计的科研工作流。OCR 与证据检索默认可离线使用；可选模型接口用于带成本提示的问答、局域综述、研究计划及公式审查解释。模型不可用、调用失败或校验未通过时，系统回退到可核对的原文片段与页码，不把模型草稿冒充事实。

本项目位于 `D:\cz\research_agent_mvp`，不会修改上级目录的赛题 PDF 或 `pdf/` 原文件。使用 Python、SQLite FTS5、`pypdf`、`pypdfium2`、`RapidOCR/ONNX Runtime` 和原生 HTML/CSS/JavaScript；**OCR 与证据检索无须模型 API Key，也能离线运行**。

## 本地启动

在 PowerShell 中：

```powershell
cd D:\cz\research_agent_mvp
python -m pip install -r requirements.txt
python app.py
```

打开 `http://127.0.0.1:8765/`。退出时按 Ctrl+C。要求 Python 3.9+，默认只监听本机；**不应直接暴露到公网**。数据库和通过网页上传的 PDF 存在 `research_agent_mvp/data/`。

页面顶部可用 **A− / A+** 按钮缩放页面（85%–160%）、“恢复默认布局”重置字号/栏宽；拖动文献库或 Agent 栏旁的竖线调整栏宽，也可聚焦竖线按方向键以 20px 微调（Home/End 调至边界）。两侧栏可独立收起与展开；“Agent 专注模式”暂时隐藏阅读区、让 Agent 面板占满页面；窄屏会改为竖向排列。布局保存在本机浏览器存储。Agent 审计记录可点“放大审计记录”全屏阅读，按 Esc 或“关闭”返回。**页面缩放不会改变原始 PDF 文件**；PDF 内部的单独缩放仍由浏览器 PDF 阅读器控制。

选择一篇已解析论文后，系统会自动启动不收费的本地准备流程：论文信息/章节导航、References 候选、结构候选、Future Work 线索、局域引用图和整库前沿线索。翻译、联合公式 AI 解读、AI 写作/拓扑、近期论文联网查询、确认下载、删除和替换版本等可能产生费用或改变数据的动作仍需用户明确点击；自动流程失败会在对应面板显示，不伪装成完成。

使用本机 Chrome 的无头验收脚本 `python tools/capture_ui_smoke.py` 可基于**隔离的临时示例库**生成 `tests/ui_qa_desktop.png` 与 `tests/ui_qa_narrow.png`，并在已安装 `websocket-client` 时测试实际浏览器里的缩放、收起、拖拽、专注、审计弹窗、问答/框架表单提交和窄屏排列。此脚本**不验证**已导入 PDF 在各浏览器的翻页、原生阅读器缩放或结构识别正确性。

首次安装需下载 OCR 推理依赖（数十 MB），后续本地识别不依赖云端 API。只有当 `requirements.txt` 中所有依赖均已安装，才可以跳过安装步骤。接口和前端无 Node 构建环节。`PORT=9000` 可以更改端口。

### 演示最短路线

1. 左侧“导入样例”依次选择 `1706.03762v7.pdf`、`1706.03762v1.pdf`；等状态变成“已解析”，查看正文近重复提示。点击任一版本，再点“查看候选差异”；候选两侧页码可以直接打开原 PDF 核对。新导入版本卡片还有“保留库中版本 / 用本次版本替换 / 两版都保留”；以旧 v1 替换较新 v7 须二次确认。正式演示前建议在测试数据库操作，避免删除现有记录。
2. 选择文献，在内嵌 PDF 阅读器中查看原论文。
   原文上方可展开论文信息卡、章节目录、数字型 `[n]` 引文列表和“本页结构候选”。后者可输入 PDF 物理页码、点击上下页检查任意页；除了全页标注图，还能点“查看图表裁剪”显示从原 PDF 渲染的实际局部图像（`/api/papers/<id>/visual-crop?page=5&visual=0`）。裁剪范围为启发式候选，可能含周围正文或缺部分图形，须对照 PDF 核验；不是理解图形含义。不能把“未检测到”解读为“没有图表”。`1706.03762v7.pdf` 的“3.2.2 Multi-Head Attention”跳到第 4 页，`[1]` 文中首次出现和参考文献条目分别跳到第 3 页和第 10 页。
   作者、机构、摘要和标题树只在阅读器上方“论文信息／章节目录”显示；阅读器导航栏可拖动右下角调整宽高，论文信息卡在宽屏也可水平拖宽。阅读器下方单独的“参考文献下钻”用于按原文页核对 arXiv 作品和确认入库；另有“文档结构总览”，现只展示跨页图表、公式、参考文献区域和附录候选，避免重复。图表组自动加载前六张原 PDF 裁剪缩略图，其余图注可点“从原 PDF 截图”。布局检测现优先用矢量绘图／图像几何定位**图下方的图注**；官方 *Emergent Abilities of Large Language Models* 的 Figure 2（PDF 第 4 页）已验图形区域会进入截图，不再只截图注文字。图像裁剪仍是启发式区域，可能含其他元素或不完整，**不意味着图像语义已理解、LaTeX 已恢复或扫描表格完整结构化**。
3. 在问答输入 `Transformer base model GPU`，系统使用 BM25 和本地 TF-IDF/LSA 潜在语义压缩的两路检索，按倒数排名融合；单击回答附带的原文证据，展示由原 PDF 渲染的页面和**尽力匹配的短句高亮**。若短句无法唯一定位，显示整页而不伪称精确锚点。未配置模型时**只提供原文片段，不会伪装成事实答案**。
   展开“Agent 审计记录”可查看问题、检索模式、证据 chunk ID、步骤、结果模式和时间。
   展开“复合任务”，勾选论文并输入“比较两篇论文的注意力机制并查看未来工作与局域引文图谱”，系统会依序调用本地工具并展示证据。若已配置模型，可确认最多两次可能计费请求：白名单工具规划和命中原文之后带 `[n]` 引文的回答草稿；越权/未配置自动回退规则路由，绝不据此自动下载或删除。
   展开“多篇论文证据对照”，勾选 2–4 篇已解析论文，沿用问题生成按论文分组的原文证据矩阵。
   输入“两篇论文有无共同点?”到常规问答时，会提示展开“多篇论文证据对照”并勾选两篇；已勾选两篇时点击常规提问可直接触发对照。输入同一问题到“复合任务”时，规则路由也要求先勾选两篇；勾选后展示两篇各自的首页原文及页码，提示补充方法、任务或数据集等比较维度；**不声称自动判定两篇论文确有相同科研结论**。
   例如点选《Attention Is All You Need》后问 `Transformer base model GPU`，即使没有配置模型也会显示 PDF 原文片段和页码；问“这篇论文讲什么?”则展示**选中论文**首页原文，并提示查看论文信息卡里的摘要，绝不把首页当成自动科研总结。全中文抽象问题若未含匹配术语，会显示明确的无证据提示，而不是空白页面。
   对问题“该模型使用什么数据集”，新增保守的中文→英文词映射（dataset/benchmark），有对应词项时输出原文 PDF 页。对“采用的骨干模型是什么”会检索编码器/骨干相关原文：CEA.pdf PDF 第 4 页明确描述两个冻结证据通道 CLIP ViT-L/14 与 DINOv3 ViT-B/16；接口 401 时会显示**原文两句摘录**及证据页，但不会把数据集倒推成骨干模型、也不会冒充 DeepSeek 推理。Agent 审计默认折叠，展开后默认只显示最近 5 条，可显式查看全部 20 条或放大阅读。
   对用户上传的 ScienceDirect 论文，已过滤 `Contents lists available at ScienceDirect` 等封面栏头，题名从文章页首抽取；`a b s t r a c t` 等空格标题和换行论文题名可识别。CEA.pdf 经本地核对可展示 Guichao Zhou / Yuwu Lu、机构及摘要。“该模型架构”会保守地检索原文 `framework`、`architecture`，展示命中的 PDF 页（仅词项映射，不等于自动理解论文架构）。没有匹配词时审计记录为 `no_evidence`，表示本次检索未找到可引用片段，而非 PDF 未导入或没有 Agent 审计。
4. 输入研究想法并勾选已解析论文，生成带原文片段/页码的论文框架候选；无证据时不生成虚构 References。可另点“核对所选论文官方作者/年份”，逐篇通过 arXiv 精确编号核实元数据，题名不符会标冲突；**即使元数据一致，也不能证明文献支持某个写作观点**。
   框架默认是**本地规则模板**，现已对未入选文献显示原因并记录审计 ID。若已配置模型，可自愿勾选“请求模型生成背景草稿”：仅将命中原文发送给指定模型，输出逐句引用/数字检查通过后才展示，失败回退基础模板；**规则未能证明语义支持、没有自动生成可投稿论文**。未配置时选项禁用。
   “把模型迁移到遥感领域”等迁移意图会额外输出**待验证研究计划**（源方法核实、目标域检索、基线/消融和评测）；对无 arXiv ID 的已选论文也展示可点击的本地 PDF 原文片段，但不伪造 References。若原文已出现 EuroSAT 等目标域词项会警告“不能直接声称创新”，需人工核查是否已有相同实验；无目标域命中也不等于无先例。此模块用于前期计划和写作提纲，**不是已完成的遥感适配实验或可靠的自动写作**。
   展开“可复制架构拓扑图”，生成固定科研工作流程的 Mermaid 源码及本地 SVG 预览；**并非自动理解 Idea 后生成专属模型架构**。
5. 再导入 `1607.06450v1.pdf`（*Layer Normalization*），点击“刷新”局域引文图：应看到 *Attention Is All You Need* → *Layer Normalization* 的引用边。输入论文题名/arXiv ID 可定位节点；选择证据类型筛边；点节点可高亮直接引用与被引邻居及相应边列表。点击边的“第 10 页”核对 Transformer 的 References 原文；查看局域 PageRank 与入度。图中合并同一 arXiv ID 的多个版本。随后上传下面的 CSV 试用图表与确定性图注：
   “生成带证据的局域引用摘要”只陈述带来源页码的引用事实，不推断技术优劣或领域演进。

```csv
epoch,accuracy
1,0.72
2,0.78
3,0.83
```

6. 导入 `1706.03762v1_img.pdf`，观察逐页 OCR 进度，完成后就其内容提问；点击证据会尝试用问题词匹配已保存的 OCR 行框并高亮扫描原图。若匹配不可靠，显示整页而不伪称精确定位。CPU 识别 15 页可能耗时数分钟；若旧记录已有 OCR 文本但没有行框，点击“重建OCR定位”。可另导入 `UnderstandingDeepLearning_02_09_26_C.pdf` 验证后台分批索引。
7. 如有网络权限，在左侧输入论文题名查询 **arXiv 官方公开元数据**，核对题名、作者、日期及编号后按“确认并下载入库”。下载失败会报告网络错误，不会假装已入库；没有自动下载所有参考文献。
8. 可展开“探索近期论文”，输入主题手动获取 arXiv 最近投稿；展示关键词推荐理由、点赞/踩与元数据中明确给出的仓库链接；没有找到仓库链接标“未发现，开源状态未知”，不能标“未开源”。期刊/会议优先显示 arXiv 自报 `journal_ref`，缺失时谨慎显示作者备注中明确的会议声明及来源；没有该字段则“未知”。**尚未接入 DBLP/Crossref 的二次检索，也没有有授权/年份可溯源的 JCR 影响因子数据库**；因此不能因 arXiv 未填 venue 就断言未发表，不能猜影响因子，会议也不适用期刊影响因子。折叠/展开不会删除当前结果，刷新页面会显示本机浏览器缓存的上次结果（标注非实时，可重新查询）。每条可点“核对并下载 PDF 入库”：再次查询官方编号/题名/作者/日期，通过一致性检查、用户确认后才下载单篇并解析；未核对、冲突、取消或网络失败都不标已下载。**当前机器访问 arXiv / Crossref 仍返回 WinError 10013，无法用第二条联网路径得到真实发表/代码/IF 事实；旧缓存不代表实时数据。**
   另外可展开“定期主题追踪”订阅主题；本机服务运行期间按 6 小时、24 小时或 7 天定时抓取最多 20 条（后端单次上限 50），保存新增作品及版本更新的元数据和运行/错误记录，支持立即刷新与暂停/恢复。**服务停止时不会运行；仅查最近固定窗口，不保证获取全部新稿，也绝不自动下载 PDF。**
9. 选中论文后，展开阅读器的“参考文献下钻”：数字型 `[n]` 按原文编号；作者—年份制论文无 `[n]` 时，仅将 References 区含明确 arXiv ID 或作者样式+年份的片段列为**合成候选**，标明列表序号不是原文引用编号。只有明确 arXiv ID 才能查询官方元数据，核对后人工确认单篇下载；无 ID 不猜测下载地址。
10. 选中已解析的论文，在“Future Work 证据线索”点“分析当前论文”：查看明确 Future Work / 计划句及 “Limitations and Outlook” **限制与展望候选**，两者分别标记；每条可自愿确认后将该原文片段送到模型翻译为中文，英文原文保留供核查；若模型 401，翻译明确失败。无命中时可前往结论/讨论页人工核查。CEA 论文 “Limitations and Outlook” 在 PDF 第 9 页，但不等同作者已承诺开展具体未来研究。面板仅依据 arXiv 编号推定**初投月份前后**，共同词不证明技术相关，时间不是正式发表日期，更不能推断已解决。
11. 在阅读器“原译对照阅读”选择页码（每批最多 100 页、600 块），先估算可能的模型请求和费用再明确确认；后台逐块保存译文，点“对照阅读”进入分页双栏，原译栏划词翻译，已生成译文可通过悬停预览，同一页的原译栏按块双向联动滚动，导出 HTML/Markdown。**原 PDF iframe 内直接划词/悬停、跨页自动连续滚动、保持版式的 PDF 导出尚未实现；DeepSeek 若返回 401 则无法生成译文**。401 代表服务端密钥认证失败，应在 DeepSeek 控制台更换已泄露密钥，并在本地 `.env` 更新后重启服务；无法由前端伪造译文。

如果旧版本程序曾将扫描件标为“需 OCR”，更新依赖并重启服务后，点击文献卡片的**“重新解析”**即可复用原 PDF，不必重新上传。

### 可选 Docker Compose（仅本机）

已提供 `Dockerfile` 和 `compose.yaml`。从本目录执行 `docker compose up --build -d`；官方 `../pdf` 只读挂载，数据保存在 Docker 命名卷，默认宿主端口仅绑定 `127.0.0.1:8765`。如已有本地服务占用 8765，可在同一 PowerShell 会话先运行 `$env:SOURCELAB_HOST_PORT="8766"`，再运行 Compose；后续查看状态或重启时保持同一端口配置。已经构建好的镜像可用 `docker compose up --no-build -d` 启动。Compose 可能读取本目录的 `.env` 并向容器传入模型配置；不要提交或公开真实密钥。该方案仍不具备公网身份认证，请勿修改绑定地址后直接对公网开放。

**Docker 实测（2026-11-17，本机 Linux/amd64 引擎）**：构建成功（Debian 系统包与 `requirements.txt` 均安装），容器在 `127.0.0.1:8766` 达到 `healthy`；`/api/health`、首页、`/api/papers` 可访问。容器从只读挂载的官方样例导入 Transformer v7（15 页）和 Layer Normalization v1（14 页），均解析为 `ready`；局域图为 2 节点、1 条引用边，PDF HEAD 可访问。重启容器后两篇论文仍在命名卷中。这是本机功能验收，**不代表公网部署、高并发或全部 PDF 版式验收**。当时直连 Docker Hub 失败，改从 Google 官方 Docker Hub 缓存拉取相同的 `python:3.11-slim` 镜像，标记为本地 `python:3.11-slim` 后使用 `docker compose build --pull=false`；缓存可用性因网络环境而异。

如需单独在公网服务器部署，参见 [`PUBLIC_DEPLOYMENT.md`](PUBLIC_DEPLOYMENT.md) 的独立 `compose.public.yaml` + Caddy HTTPS/整站鉴权方案；它不与本机 Compose 合并，且**仅完成配置/网关语法检查，尚未在公网服务器实际验收**。不要直接公开本机的 8765/8766。

### 可选的模型草稿

如果你**已经有**兼容 Chat Completions 消息格式的模型服务，可设置环境变量后启动：

```powershell
$env:LLM_CHAT_ENDPOINT="http://127.0.0.1:11434/v1/chat/completions"
$env:LLM_MODEL="你的模型标识"
$env:LLM_API_KEY=""
python app.py
```

此时问答会把检索片段发给配置的服务，请注意文献隐私与 API 费用。模型输出会明确标注为**草稿**，不是“已验证的回答”；点击原文证据人工核对。未设置/不可用则退回离线证据模式。

本项目会自动读取 `research_agent_mvp/.env`（该文件已被 `.gitignore` 忽略）。DeepSeek 配置示例为 `LLM_CHAT_ENDPOINT=https://api.deepseek.com/chat/completions`、`LLM_MODEL=deepseek-chat`、`LLM_API_KEY=你的密钥`。不要把 `.env` 上传到 GitHub/Gitee，也不要把密钥写进前端代码。页面顶部显示“模型接口已配置”只代表配置项已读到；首次真实提问仍可能因余额、权限、网络或接口限流失败，失败时系统会退回原文证据模式。
如果审计显示 HTTP 401，证明模型端拒绝密钥，**不能通过前端开关修复**。应撤销曾发布/泄露的密钥，在模型供应商控制台重新创建密钥、在本地 `.env` 更换 `LLM_API_KEY`、重启 `app.py`；切勿把新密钥发送到聊天中。401 时仍可运行本地 PDF 证据检索和图表裁剪，但模型翻译/生成不可用；请求失败后的实际费用以供应商账单为准。
**`.env` 只在服务启动时读取**；修改文件但不重启时，旧进程仍使用旧密钥。可运行 `python tools/check_model_auth.py` 做只读鉴权检查：只请求 DeepSeek 官方 `/models`，不发送论文片段、不触发文本生成、不回显密钥；`AUTH_OK; configured_model_available=True` 只说明鉴权及模型列表可读，**不能保证之后的生成/翻译请求成功**。请在重启网站后再从页面明确确认一次付费请求并查看新的审计错误；此前的 401 历史不会自动消失。
**HTTP 404 排障**：本项目使用 Python `urllib.request` 直接 POST 到 `LLM_CHAT_ENDPOINT`，必须填写完整的 `https://api.deepseek.com/chat/completions`，不能只填写 `https://api.deepseek.com`（那只是 SDK 的 base URL）；只读 `/models` 检查通过也不代表聊天 URL 填写正确。检查脚本现在会先拒绝不完整的 URL。

若要显示费用估算，可在 `.env` 增加你账户实际价格（单位 USD/百万 tokens）：
`LLM_INPUT_USD_PER_MILLION=...`、`LLM_OUTPUT_USD_PER_MILLION=...`。系统只使用模型返回的 usage 计数；若供应商未返回 usage，页面会明确显示“无法确认费用”，不会自行猜测。

## 安全与数据说明

- API 无身份验证，仅供本机演示。不要修改监听地址为 `0.0.0.0` 并直接放到公网。
- 默认不上送 PDF 给第三方。只有配置模型服务并提交问答时，才会将命中的片段发送到该服务。
- OCR 模型在本机 CPU 推理，无须上传 PDF；按页处理并记录成功页数。OCR 文本可能存在错误，引用仍需对照 PDF 原图人工核查。
- 证据页预览根据检索命中的 `chunk_id` 查库（不接受客户端自定义 PDF 路径或坐标）；矢量文本短句可能出现在一页多处，高亮位置并非人工审核的段落坐标。对扫描件没有 OCR 框位置回填，只能核对整页。
- OCR 行框是归一化到渲染页的检测框，并非版面语义段落框；高亮需要问题词与 OCR 片段有足够重合，避免“总是高亮第一页”。OCR 识别错误、行切分和双栏顺序都可能导致没有高亮或误高亮。
- 本地 LSA 是统计潜在语义的轻量基线，首次查询需要基于已导入文档重新计算，长书可能产生额外等待和 CPU 占用；大型库（超过 6500 个片段）自动退回 BM25。并不保证跨语言、公式、表格或冷门实体的检索质量；两个方法的原始排名与页码可以通过 `tests/evaluate_official.py` 对比。
- 原 PDF 路由支持 HTTP Range 和 HEAD，浏览器可按需加载大文件；仅本机无认证环境下使用。
- 版本号/arXiv ID 基于文件名或首页文本识别，未向 arXiv 官方核验；版本对比还会检查抽取题名是否一致，**仍须人工确认论文身份**。差异报告限制前 20,000 个抽取词，数字变化可能只是参考文献编号或抽取误差。
- arXiv 题名检索访问其官方公开 Atom API；实际下载由用户点击确认，后端只构造 `https://arxiv.org/pdf/{数字型ID}`。运行服务的进程必须拥有外网访问权限；沙箱、离线机器或代理故障会显示网络错误。请遵守目标站点资源与使用规定，不要用于批量爬取。
- 引文边只匹配已导入文献，严格要求检测到源论文的参考文献区；若 PDF 解析丢失该标题，会漏掉边。入度和 PageRank 仅对当前导入的一小批论文计算，数据量少时不能宣称“全领域基石文献”。题名相似也可能误匹配，应逐边核对原文。
- 上传限制 30 MB，仅接收以 `%PDF-` 开头的文件；没有 PDF 内容杀毒/沙箱。请只处理可信文件。
- `data/` 保存本地索引和上传论文，不要提交到公开仓库或打包给评审（除非有权分享论文）。
